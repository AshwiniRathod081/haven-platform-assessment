# B0 – The Terraform count trap

## What happens when a landlord account is removed?

The current Terraform configuration uses `count` to create one S3 bucket per landlord account.

```hcl
resource "aws_s3_bucket" "landlord_media" {
  count  = length(var.landlord_accounts)
  bucket = "haven-media-${var.landlord_accounts[count.index]}"

  tags = {
    landlord_account_id = var.landlord_accounts[count.index]
  }
}
```

Terraform identifies these resources using positional indexes rather than stable landlord account IDs.

Initially, the list contains:

- Index 0: la-001
- Index 1: la-002
- Index 2: la-003
- Index 3: la-004

After removing la-002, the list becomes:

- Index 0: la-001
- Index 1: la-003
- Index 2: la-004

## What does terraform plan show?

I reproduced this using:

```bash
terraform plan -refresh=false -var-file="$env:TEMP/haven-b0.tfvars"
```

The plan showed:

- `landlord_media[1]` must be replaced because its bucket name changes from `haven-media-la-002` to `haven-media-la-003`.
- `landlord_media[2]` must be replaced because its bucket name changes from `haven-media-la-003` to `haven-media-la-004`.
- `landlord_media[3]` will be destroyed because index 3 is no longer in the list.
- `landlord_media[0]` remains unchanged.

The plan summary was:

```text
Plan: 4 to add, 0 to change, 3 to destroy.
```

The additional creation of listing_media and its lifecycle configuration is unrelated to the count-indexing issue.

## Why is this dangerous?

S3 buckets can contain important landlord documents and property photos. Removing one landlord from the middle of the list shifts the indexes of the remaining accounts.

As a result, Terraform may replace buckets belonging to other landlords or destroy an existing bucket that is still required.

This can cause data loss, service disruption and unexpected infrastructure changes.

## What is the fix?

Use `for_each` instead of `count`, with the landlord account ID as the resource key.

```hcl
resource "aws_s3_bucket" "landlord_media" {
  for_each = toset(var.landlord_accounts)

  bucket = "haven-media-${each.key}"

  tags = {
    landlord_account_id = each.key
  }
}
```

With `for_each`, Terraform identifies each bucket using its landlord account ID rather than its position in a list.

Removing la-002 would then affect only the resource associated with la-002. The other landlord buckets would retain their identities and would not be replaced merely because another account was removed.

**Conclusion:** For resources that represent independently identified entities, such as landlord accounts, `for_each` with stable unique keys is safer than positional `count` indexing.
